Индекс задач по этапам. Спецификация — `docs/spec/spec.md`.

## Как вести прогресс

- Отмечайте задачу как выполненную только по критерию «Готово когда» — не по факту написания кода.
- Если критерий не выполнен, но задача начата, оставляйте `[ ]` и пишите статус в строке задачи:

```markdown
- [ ] **T-<этап>.<N> Название задачи** — 2д · FR-DIFF-1 · в работе: осталась свёртка контекста
```

- Заблокированная задача помечается так:

```markdown
- [ ] **T-<этап>.<N> Название задачи** — 2д · заблокировано: нужен relay из этапа 5
```

- Текст задачи не переписывайте. Если объём изменился, добавляйте подпункт «Уточнение:» — иначе теряется история планирования.
- Новые задачи, обнаруженные по ходу, добавляйте в конец своего этапа с номером `T-<этап>.<следующий>` и пометкой «Найдено в работе:».
- Порядок задач внутри этапа — рекомендуемый. Обычно «Зависит» указывает на задачу с меньшим номером. Если задача нужна раньше, чем позволяет её номер, в строке «Зависит» стоит пометка «вне очереди» — такую задачу берут в работу до тех, кто на неё ссылается.

## Формат задачи

```markdown
- [ ] **T-<этап>.<N> Короткое название** — оценка · FR-ID, FR-ID
  - Зависит: T-<этап>.<M>, «все предыдущие задачи этапа» или «—»
  - Готово когда: проверяемый критерий. Не «реализовано», а «на экране X при условии Y наблюдается Z».
```

Оценка: `1д`, `2д`, `3д` — порядок величины, не обязательство.

Условная задача (например, при гейте T-7.17) может быть закрыта решением «не нужна: гейт не пройден» — причина записывается в строке задачи.

## Правило разбиения этапа на подзадачи

Этап считается закрытым, когда все его задачи отмечены и пройден сквозной сценарий этапа (последняя задача каждого файла — «Сквозная проверка этапа»; задачи, найденные в работе и дописанные после неё, входят в «все предыдущие задачи этапа» только по явной ссылке).
