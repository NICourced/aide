# Этап 3. API и Tools

**Цель этапа:** агент работает не только с файлами и терминалом, но и с внешним миром. Пользователь подключает внешние API (OpenAPI/Swagger, GraphQL, gRPC, REST, MCP), получает набор tools с типами и проверкой аргументов, заводит секреты в защищённом хранилище платформы, задаёт раздельные разрешения на чтение и запись, а всё исполнение идёт в песочнице хоста. Управление — из bottom sheet, с полным логом вызовов, стоимостью и изоляцией от ФС хоста и от сети (§ 5.7, § 10.1).

**Не входит в этап:** роли агентов и детерминированные проверки как отдельный слой (этап 4); транспорт удалённого подключения — relay / VPN-меш / SSH-туннель, § 3.3 (этап 5); производительность — Rust-модули, инкрементальная индексация, офлайн-кэш (этап 6); AST-aware diff, semantic merge, CRDT (этап 7); iOS и macOS (этап 8); Preview-экран в объёме, вынесенном за MVP (этап 5). Магазина готовых tools и обмена tools между пользователями в spec.md нет — этап под это не заводится.

**Сквозная проверка этапа** — последняя задача (T-3.28).

## Реестр tools, типы и права

- [ ] **T-3.1 Реестр tools со схемами аргументов** — 2д · FR-TOOLS-2, § 8.2
  - Зависит: T-1.12
  - Готово когда: модуль `host-tools` хранит записи реестра (имя, описание, источник подключения, схема аргументов, тип операции — чтение или запись, текущее разрешение, цена вызова — ставка либо `бесплатно`); вызов имени, которого нет в реестре, возвращает агенту ошибку «tool не найден» и не выполняется молча; состав реестра, цена и разрешения переживают перезапуск хоста (БД хоста, T-0.16), добавление поля цены проходит миграцию схемы; на реестре из 50 tools поиск по имени и фильтр по источнику возвращают ожидаемые наборы (проверено тестом с фиксированным списком).

- [ ] **T-3.2 Проверка аргументов вызова** — 2д · FR-TOOLS-2, FR-TOOLS-4
  - Зависит: T-3.1
  - Готово когда: аргументы проверяются по схеме tool до обращения к внешнему сервису; на наборе из 8 случаев (пропущено обязательное поле, лишнее поле, строка вместо числа, значение вне перечисления, вложенный объект неверной формы, массив вместо скаляра, `null` в обязательном поле, корректный вызов) каждый даёт ожидаемый вердикт; сообщение об ошибке называет путь до поля (например `body.items[2].sku`) и причину; в логе видно, что внешний вызов не состоялся; на неверных аргументах счётчик обращений к внешнему сервису в тестовом стенде равен нулю.

- [ ] **T-3.3 Возможности внешних вызовов и жёсткие запреты** — 2д · FR-TOOLS-8, § 10.1
  - Зависит: T-1.12, T-3.1
  - Готово когда: расширяет T-1.12: у внешнего tool раздельно настраиваются разрешения на операции чтения и записи, а также отдельно — исходящая сеть и доступ к секрету; выдача `allow` на чтение не открывает запись (тест на tool с двумя операциями: чтение проходит без подтверждения, запись требует подтверждения); запись вне воркспейса и вызов произвольного адреса остаются запрещёнными при любых настройках — проверяется попыткой включить их через API хоста и подменой файла настроек вручную; попытка отклоняется с ошибкой доступа, а не «тихо игнорируется».

## Подключение внешних API

- [ ] **T-3.4 Импорт OpenAPI/Swagger: генерация набора tools** — 3д · FR-TOOLS-1, FR-TOOLS-2, FR-TOOLS-9
  - Зависит: T-3.1, T-3.2
  - Готово когда: указание файла спецификации (OpenAPI 3.x, JSON или YAML) или URL даёт список tools на подтверждение; каждый tool получает имя, описание из `summary`/`description`, схему аргументов из `parameters` и `requestBody`, а тип операции — из HTTP-метода; после подтверждения tools попадают в реестр с разрешением `ask`; проверено на спецификации из 20 операций — число tools совпадает с числом операций, а схема одной операции по обязательным полям и типам совпадает с исходной; спецификация из 500 операций импортируется с прогрессом и не подвешивает клиент (проверяется на ширине 360 dp и на десктопе); вложенные `$ref` разрешаются в плоскую схему без потери обязательных полей.

- [ ] **T-3.5 Импорт GraphQL-схемы** — 3д · FR-TOOLS-1, FR-TOOLS-2
  - Зависит: T-3.1, T-3.2
  - Готово когда: по SDL-схеме (файл или introspection-запрос) генерируются tools для выбранных операций: имя из имени поля, аргументы из аргументов поля, типы из схемы; проверено на схеме с 3 query и 2 mutation — mutation помечается как операция записи и требует подтверждения, query — как чтение, `enum`-аргумент даёт перечисление с тем же набором значений; операция с обязательным аргументом-объектом даёт вложенную схему, а не «любой JSON»; невалидная SDL отклоняется с указанием строки и столбца ошибки.

- [ ] **T-3.6 Импорт gRPC по proto** — 3д · FR-TOOLS-1, FR-TOOLS-2
  - Зависит: T-3.1, T-3.2
  - Готово когда: подключение выполняется по `.proto` (файл или набор с импортами): сервисы и методы видны списком, выбранные методы становятся tools; схема аргументов собирается из message-типов, вложенные message разворачиваются во вложенные объекты, повторяющиеся поля — в массивы; на proto с 4 сервисами и 15 методами импорт даёт 15 tools; метод с потоковым ответом либо поддержан с явным лимитом на размер ответа, либо отклоняется с понятным сообщением, но не роняет хост; недоступность сервиса при тестовом вызове даёт ошибку с кодом состояния, а не пустой ответ.

- [ ] **T-3.7 Подключение MCP-сервера** — 3д · FR-TOOLS-1, FR-TOOLS-2
  - Зависит: T-3.1, T-3.2
  - Готово когда: хост подключается к MCP-серверу (локальный процесс или сетевой адрес), получает список tools с их схемами и регистрирует их с источником «MCP» и разрешением `ask`; при недоступности сервера подключение завершается ошибкой с причиной, а tools других источников продолжают работать; повторное подключение к тому же серверу не создаёт дубликатов (проверяется счётчиком записей реестра); при обрыве соединения с сервером во время прогона агент получает ошибку вызова, а не зависание (таймаут не больше заданного).

- [ ] **T-3.8 Обновление спецификации и конфликты имён** — 2д · FR-TOOLS-2
  - Зависит: T-3.4
  - Готово когда: повторный импорт изменённой спецификации показывает изменения состава: добавленные, изменённые и исчезнувшие tools; изменившаяся схема аргументов не подменяется молча — нужно подтверждение, и до него вызовы идут по прежней схеме; tool, исчезнувший из спецификации, не удаляется, а помечается устаревшим, и его прежнее разрешение сохраняется до решения пользователя; имя, совпадающее с именем tool из другого источника, получает различимый суффикс, и это видно в списке импорта; отказ от подтверждения оставляет реестр в состоянии до импорта.

## Конструктор tools

- [ ] **T-3.9 Конструктор: форма описания tool** — 2д · FR-TOOLS-3, FR-TOOLS-9
  - Зависит: T-3.1, T-3.2
  - Готово когда: в конструкторе задаются имя, описание, адрес и метод, схема аргументов (полями формы или вставкой схемы), отображение аргументов в параметры запроса и разбор ответа; сохранение без имени или с пустой схемой аргументов блокируется с указанием причины; некорректная схема отклоняется с позицией ошибки; сохранённый tool появляется в реестре с разрешением `ask` и доступен агенту без перезапуска хоста; сохранение без проверки невозможно (кнопка «Сохранить» неактивна, пока форма не прошла проверку).

- [ ] **T-3.10 Tool к REST-сервису без спецификации** — 2д · FR-TOOLS-1, FR-TOOLS-3
  - Зависит: T-3.3, T-3.9
  - Готово когда: через конструктор создаётся tool к REST-сервису без OpenAPI: путь с подстановками (`/v1/items/{id}`), query-параметры, тело и заголовки; агент вызывает его по сгенерированной схеме; ответ сохраняется в лог целиком либо обрезается по лимиту с точным числом отброшенных байт; ошибка HTTP (4xx, 5xx) передаётся агенту с кодом и телом ответа, а не как «пустой ответ»; отсутствие обязательного параметра пути даёт ошибку валидации до сетевого вызова.

- [ ] **T-3.11 Тестовый вызов до сохранения** — 2д · FR-TOOLS-3, FR-TOOLS-4
  - Зависит: T-3.9, T-3.12, T-3.14 (вне очереди: маскирование секретов в тестовом запросе)
  - Готово когда: до сохранения конструктор выполняет тестовый вызов и показывает собранный запрос (метод, адрес, заголовки без значений секретов, тело), ответ, длительность и ошибки валидации; для tool, помеченного безопасным (только чтение), вызов не меняет состояние на стороне сервиса и не создаёт снапшот — проверяется тестовым стендом, который отвергает изменяющие запросы и считает их отдельно; для tool, не помеченного безопасным, показывается предупреждение о возможных последствиях и требуется явное подтверждение; недоступность сервиса показывает причину (таймаут, ошибка имени, отказ TLS), а не «ошибка»; тестовый вызов пишется в журнал как отдельная запись с признаком «тест из конструктора».

## Менеджер секретов

- [ ] **T-3.12 Хранилище секретов на платформенные API** — 3д · FR-TOOLS-5, FR-TOOLS-6, § 9
  - Зависит: T-0.1, T-3.1
  - Готово когда: секреты хранятся в защищённом хранилище платформы (Android Keystore, libsecret на Linux, DPAPI на Windows) и доступны хосту по идентификатору, а не по значению; значение секрета не возвращается в клиент ни одним сообщением протокола (перехват кадра протокола при открытии карточки секрета не содержит строки значения); при недоступности хранилища tool, требующий секрет, отказывает с явной ошибкой, и приложение не переходит на хранение в файле или в БД (проверяется отключением сервиса хранилища на Linux); после перезапуска хоста секрет доступен без повторного ввода.

- [ ] **T-3.13 OAuth: получение и автообновление токенов** — 3д · FR-TOOLS-5, FR-TOOLS-7
  - Зависит: T-3.12
  - Готово когда: поддержаны client credentials и authorization code; access- и refresh-токены хранятся как секреты; при истечении access-токена обновление выполняется до внешнего вызова, и вызов уходит уже с новым токеном (проверяется стендом авторизации, который принимает только свежий токен и отвергает просроченный); при неудачном обновлении агент получает явную ошибку с указанием, какой секрет требует повторной авторизации, а не пустой ответ; 5 одновременных вызовов с истёкшим токеном приводят ровно к одному запросу обновления; после перезапуска хоста действительный refresh-токен используется без повторного входа пользователя.

- [ ] **T-3.14 Статические ключи и переменные окружения** — 2д · FR-TOOLS-5
  - Зависит: T-3.12
  - Готово когда: поддержаны два способа подстановки — статический ключ, хранимый как секрет, и ссылка на переменную окружения хоста (`${ENV:NAME}`); подстановка работает в заголовке, в query-параметре и в теле, по месту, указанному в конструкторе; в интерфейсе видно факт подстановки и имя источника, но не значение; ссылка на несуществующую переменную даёт ошибку при сохранении tool, а не при первом вызове агентом; значение переменной окружения не сохраняется в БД хоста (проверяется чтением строк таблицы tools после сохранения).

- [ ] **T-3.15 Секреты не попадают в логи, снапшоты и промпты** — 3д · FR-TOOLS-6, NFR-8, § 9
  - Зависит: T-1.19, T-3.12
  - Готово когда: значения секретов отсутствуют в логах хоста, журнале вызовов, снапшотах и тексте промпта агента; проверка — тест: секрет со значением-маркером `AISTUDIO_SECRET_MARKER_9f3` используется в вызове, после прогона поиск по файлам логов, журналу аудита, содержимому снапшотов и трассе промптов не находит маркер; в логе на месте секрета стоит метка вида «секрет: github_token»; если сервис вернул секрет в теле ответа, при записи в журнал он также маскируется по списку известных значений; маскирование применяется и к аргументам подтверждения, показываемым пользователю.

## Разрешения и подтверждения

- [ ] **T-3.16 Разрешение: на один вызов, на сессию, постоянно** — 2д · FR-TOOLS-11, § 10.1
  - Зависит: T-1.13, T-3.3
  - Готово когда: все три варианта выдачи различимы в модели прав; выданное на один вызов не запоминается ни в БД, ни в памяти — второй такой же вызов снова требует подтверждения; выданное на сессию действует до перезапуска хоста и явно помечено в интерфейсе как временное; постоянное переживает перезапуск хоста и видно в списке разрешений; для tool с раздельными правами выдача на запись не меняет разрешение на чтение и наоборот (тест на tool с двумя операциями); выдача на один вызов не создаёт записи в таблице разрешений.

- [ ] **T-3.17 Подтверждение вызова внешнего tool и отказ** — 2д · FR-TOOLS-8, § 6.1, § 6.3
  - Зависит: T-3.16
  - Готово когда: расширяет T-1.13 (карточку подтверждения встроенных инструментов): при разрешении `ask` карточка подтверждения показывает tool, метод и адрес, значимые аргументы (значения секретов скрыты), чтение это или запись и что изменится снаружи; кнопки «Разрешить один раз», «Разрешить на сессию», «Запретить»; отказ возвращает агенту машинно-различимую ошибку «отказано пользователем», прогон продолжается, а не падает, и агент не повторяет тот же вызов автоматически (проверяется на прогоне, где пользователь отказывает дважды подряд); обрыв связи во время `ask`: вызов остаётся в состоянии «ожидает подтверждения», после реконнекта показывается карточка того же вызова с тем же идентификатором, а повторное подтверждение не создаёт второй вызов; карточка при ширине 360 dp не требует горизонтального скролла даже при аргументе-строке в 500 символов; если разрешение уже выдано режимом автономности, подтверждение не дублируется.

- [ ] **T-3.18 Отзыв разрешения на лету и список использованных tools** — 2д · FR-TOOLS-15
  - Зависит: T-1.3, T-3.17
  - Готово когда: во время прогона панель tools показывает, какие tools агент уже использовал в этом прогоне, с числом вызовов и последней длительностью; отзыв разрешения вступает в силу до следующего вызова: следующий вызов того же tool не выполняется, агент получает отказ, а запись об отзыве есть в журнале; список обновляется без ручного обновления и сохраняет порядок появления tools; на прогоне с 30 использованными tools список прокручивается без потери позиции при сворачивании панели.

## Логи, стоимость и аудит

- [ ] **T-3.19 Лог вызовов внешних tools** — 2д · FR-TOOLS-10, NFR-10, § 10.2
  - Зависит: T-1.3, T-1.14, T-3.1
  - Готово когда: внешний слой записи: код ответа HTTP или ошибка сервиса, обрезка тела с точным числом отброшенных байт, постраничная выдача, отдельный канал журнала для внешних вызовов (схема записи — T-1.3, хранение — T-1.14); запись создаётся и при ошибке сервиса, и при отказе пользователя; журнал отдаётся клиенту постранично — прогон из 500 вызовов не выгружается одним сообщением и не блокирует интерфейс; записи за прошлые прогоны доступны после перезапуска хоста и после смены клиентского устройства.

- [ ] **T-3.20 Цена вызова и стоимость на трёх уровнях** — 2д · FR-COST-1, FR-COST-2, FR-COST-3, FR-COST-4, FR-COST-5, FR-COST-6
  - Зависит: T-1.5, T-3.19
  - Готово когда: у tool настраивается цена вызова (явная ставка либо 0 для бесплатных); стоимость суммируется по вызову, по прогону и по задаче и видна в логе и в итогах прогона (отображение итогов — T-1.5, модель — § 5.9); задаются жёсткий лимит прогона и жёсткий лимит задачи по § 5.9 — прогон останавливается между вызовами с сообщением о причине, по задаче не запускается новый прогон, а текущий доводится до ближайшего безопасного шага и останавливается, при этом уже выполненные вызовы не откатываются; снятие или подъём лимита продолжает работу с того же места; прогон из 100 вызовов с разными ценами показывает итог, совпадающий с суммой записей журнала до последней цифры; при вызове с неизвестной ценой стоимость помечается как «неизвестна», а итог по задаче — как неполный. Мягкий лимит на роль сюда не входит: он появляется вместе с ролями на этапе 4 (T-4.12), где модель § 5.9 только расширяется, а не переопределяется.

## Управление tools в интерфейсе

- [ ] **T-3.25 Bottom sheet управления tools** — 3д · FR-TOOLS-14, FR-LAYOUT-7
  - Зависит: T-1.49, T-3.4, T-3.9, T-3.12, T-3.19
  - Готово когда: все операции с tools — список, подключение, импорт спецификации, конструктор, секреты, разрешения, лог, тестовый вызов — доступны в bottom sheet из основного экрана; вкладка Tools открывает этот bottom sheet и не содержит собственного управления, отдельных админ-панели и экрана настроек tools не существует; панель не занимает постоянного места и закрывается одним жестом; список из 200 tools прокручивается без потери позиции после закрытия и повторного открытия; набор кнопок соответствует FR-CTRL-17 («Открыть», «История», «Права», «Тест», «Удалить») и расширяет панель «Файлы и tools» из T-1.44; на ширине 360 dp и на планшете 768 dp панель не перекрывает чат-ввод, а состав кнопок доступен в режимах «Жесты», «Кнопки» и «Гибрид» (§ 5.5.1).

- [ ] **T-3.26 Состояния экрана управления tools** — 2д · § 6.1, NFR-7
  - Зависит: T-3.25
  - Готово когда: проверены UI-тестами на ширине 360 dp пять состояний: «пусто» — нет подключённых tools, с подсказкой «Подключите API или создайте tool»; «загрузка» — скелетон списка при импорте спецификации из сети, без пустого экрана и бесконечного индикатора; «ошибка» — импорт не удался, показано что случилось, что можно сделать и кнопка повтора, техническая деталь по запросу; «нет связи» — список tools показан из кэша с явной пометкой, изменение разрешений недоступно и объяснено; «нет прав» — какой именно tool требует разрешения и как его выдать; в состоянии «нет связи» кэш не подменяет реальность: недоступные действия не выглядят рабочими.

- [ ] **T-3.27 Доступность панели tools** — 1д · FR-A11Y-1, FR-A11Y-4, FR-A11Y-5, NFR-11
  - Зависит: T-3.25
  - Готово когда: прогон с TalkBack проходит по списку tools, конструктору и карточке подтверждения вызова — подписи осмысленны, порядок обхода совпадает с визуальным, текущее разрешение (`allow` / `ask` / `deny`) озвучивается; каждая операция панели доступна кнопкой в режимах «Кнопки» и «Гибрид»; размер touch-target у элементов списка и кнопок не меньше 48×48 dp (проверяется линтом разметки); при системном шрифте 200 % описания tools переносятся, а не обрезаются, и кнопки панели не перекрывают список.

## Проверка этапа

- [ ] **T-3.28 Сквозная проверка этапа: внешний API в цикле ревью** — 2д · FR-TOOLS-1..15, NFR-9, NFR-10
  - Зависит: все предыдущие задачи этапа
  - Готово когда: на Android-устройстве и на десктопе выполняется полный цикл: импорт спецификации OpenAPI → подключение сервиса с OAuth-секретом → тестовый вызов в конструкторе → сохранение tool с разрешением `ask` → постановка задачи агенту, во время которой агент вызывает tool на чтение (без подтверждения) и на запись (с подтверждением) → выдача разрешения «на один вызов» и повторный вызов снова требует подтверждения → попытка соединения из песочницы на запрещённый адрес блокируется, а на разрешённый проходит → в журнале присутствуют все вызовы с длительностью и стоимостью → итог стоимости прогона совпадает с суммой записей журнала → поиск по логам, снапшотам, журналу и трассе промптов не находит значение секрета → разрешение отзывается на лету, и следующий вызов не выполняется. Все шаги пройдены через bottom sheet, без отдельной админ-панели; в журнале аудита есть все вызовы этого цикла, включая отказ пользователя и заблокированный сетевой запрос.

- [ ] **T-3.29 Стенд внешних сервисов для тестов этапа** — 2д · § 8.5
  - Зависит: T-3.1
  - Готово когда: в репозитории есть стенд из трёх частей, поднимаемый одной командой без сети: HTTP-заглушка с подсчётом обращений и отдельным счётчиком изменяющих запросов; стенд авторизации, принимающий только свежий access-токен и отвергающий просроченный; переключатель «сервис недоступен». Стенд переиспользуют T-3.2 (счётчик обращений равен нулю при неверных аргументах), T-3.11 (изменяющие запросы отвергаются и считаются отдельно), T-3.13 (обновление токена ровно один раз), T-3.28 (полный цикл); повторный запуск стенда даёт те же результаты, а попытка обратиться к реальному внешнему адресу в тестах валит прогон.
