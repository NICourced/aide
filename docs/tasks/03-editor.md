# Этап 2. Редактор-лупа

**Цель этапа:** пользователь открывает код из любой точки review-цикла, читает его с поддержкой LSP с хоста и при необходимости вносит точечную правку — вручную или через ИИ, — не покидая мобильный сценарий.

**Не входит в этап:** рефакторинги уровня десктопной IDE (extract, change signature целиком), мультикурсор и отладчик (NG1; § 2.2) — быстрые действия уровня hunk'а и символа (FR-EDITOR-20) в этап входят; конструктор внешних tools и менеджер секретов (этап 3); роли агентов (этап 4); удалённый хост через интернет (этап 5); Rust-модули и инкрементальная индексация на больших репозиториях (этап 6); AST-aware diff, semantic merge и совместное редактирование через CRDT — блокировка файла на время правки остаётся на этапе 7; iOS и macOS (этап 8).

**Сквозная проверка этапа** — последняя задача (T-2.28).

## Хост-LSP и индекс

- [ ] **T-2.1 Модуль `host-lsp`: LSP-сессия рядом с воркспейсом** — 3д · § 8.2, § 3.2
  - Зависит: T-0.11, T-0.13
  - Готово когда: хост поднимает LSP-сервер в том же окружении, где лежит воркспейс, и передаёт ему корень воркспейса в `initialize`; клиент не имеет доступа к процессу LSP: правило сборки T-0.4 не даёт `client-ui` сослаться на `host-lsp` (проверяется внесённым нарушением); на репозитории-фикстуре первая диагностика для открытого файла приходит не позже 3 с; сервер поднимается один на воркспейс, а не по одному на запрос — после 50 запросов число процессов LSP не растёт; для языка без установленного сервера модуль возвращает `LspUnavailable` со списком поддерживаемых языков, а не роняет хост.

- [ ] **T-2.2 Проксирование LSP-запросов через протокол клиент ↔ хост** — 2д · § 3.2, § 8.4
  - Зависит: T-2.1, T-0.8
  - Готово когда: определение символа, ссылки, диагностики, outline и дополнения приходят на клиент как сообщения протокола, и клиент при этом не читает файлы репозитория напрямую; у каждого запроса есть идентификатор и таймаут по умолчанию 5 с; ответ приходит асинхронно и не блокирует рендер — на файле 5000 строк тап по экрану обрабатывается за < 100 мс (NFR-2, инструментирование кадра); обрыв связи во время запроса даёт явную ошибку с кодом, а после реконнекта повтор запроса с тем же идентификатором возвращает один результат, а не два (§ 8.4).

- [ ] **T-2.3 Индекс проекта: поиск по тексту и по символам** — 3д · FR-EDITOR-8
  - Зависит: T-2.1
  - Готово когда: на репозитории-фикстуре из 2000 файлов поиск по подстроке и по имени символа отдаёт первую страницу результатов за < 1 с; каждый результат содержит путь, номер строки, диапазон совпадения и фрагмент контекста; после правки файла (агентом или человеком) результат по изменённому фрагменту появляется в поиске не позже 2 с; 200 совпадений отдаются страницами по 50 без блокировки UI; файл больше 2 МБ и файл с нечитаемой кодировкой помечаются пропущенными, а не рвут поиск; бюджеты поиска и обновления индекса уточняются на этапе 6 (T-6.3, T-6.14).

- [ ] **T-2.4 Отказоустойчивость LSP и тесты `host-lsp`** — 3д · § 6.1, § 8.5
  - Зависит: T-2.2, T-2.3
  - Готово когда: есть тесты модуля без UI и без сети — определение, ссылки, диагностики, поиск, поведение при `LspUnavailable`; тесты используют зафиксированные ответы LSP и один прогон на реальном сервере с репозиторием-фикстурой; `kill -9` процесса LSP-сервера не роняет хост: сессия перезапускается, клиент сохраняет открытый файл и позицию прокрутки; при недоступном сервере запросы определения, ссылок и дополнений возвращают состояние «недоступно для этого языка» за < 200 мс вместо ожидания таймаута; набор проходит 20 раз подряд без падений и без «залипших» ожиданий (проверяется логом прогонов).

## Вход в код

- [ ] **T-2.5 Контракт «открыть код» и стек возврата** — 2д · FR-EDITOR-5, FR-EDITOR-10
  - Зависит: T-1.28, T-0.14
  - Готово когда: существует единственная точка открытия редактора с параметрами «путь, диапазон строк, колонка, источник (diff / чат / поиск / список файлов)»; после закрытия редактора пользователь возвращается ровно в исходный элемент — тот же hunk, то же сообщение чата, та же строка списка результатов; повторное открытие того же места не удваивает стек (10 открытий одного файла требуют ровно 10 шагов «Назад»); системный жест «назад» на Android работает как кнопка «Назад» и не выходит из приложения, пока стек не пуст (§ 6.2); редактор не является точкой входа — при запуске с непроверенными пакетами открывается инбокс (FR-INBOX-1).

- [ ] **T-2.6 Открытие кода из diff** — 2д · FR-EDITOR-6, FR-EDITOR-10
  - Зависит: T-2.5, T-1.33
  - Готово когда: тап по имени файла в карточке hunk'а открывает файл на первой строке hunk'а, тап по строке кода внутри hunk'а — на конкретной строке, при этом изменённый диапазон подсвечен в редакторе; после закрытия редактора пользователь попадает в тот же hunk — проверено на пакете из 40 hunk'ов в 5 файлах: возврат не сбрасывает позицию на первый hunk и не пересобирает пакет заново; на ширине 360 dp переход выполняется одним тапом, без промежуточного меню.

- [ ] **T-2.7 Открытие кода из чата** — 2д · FR-EDITOR-7, FR-EDITOR-10
  - Зависит: T-2.5, T-2.3, T-1.40
  - Готово когда: на запрос «покажи функцию `login`» ответ агента в чате содержит переход к найденному объявлению; тап открывает файл на строке объявления и центрирует её; если символов с таким именем несколько, показывается список с путями и строками объявления, и переход возможен к любому; если совпадений нет, чат отвечает «не найдено» и редактор с пустым содержимым не открывается; на запрос без имени символа («покажи файл настроек») открывается файл без выделения строки; открытие из чата работает на уже загруженном файле без сети, с явной пометкой «кэш» (NFR-7).

- [ ] **T-2.8 Открытие из глобального поиска и из списка файлов** — 3д · FR-EDITOR-8, FR-EDITOR-9, FR-EDITOR-10
  - Зависит: T-2.5, T-2.3, T-1.49
  - Готово когда: результат поиска открывает файл на строке совпадения и выделяет найденный фрагмент; возврат из редактора сохраняет текст запроса и позицию прокрутки списка результатов — проверено на 200 результатах: возврат попадает на тот же экранный пункт, а не в начало списка; вкладка «Файлы» открывает файл по тапу и показывает его путь; список из 500 файлов прокручивается без потери кадров (NFR-3); при переходе по результату из файла вне текущего пакета редактор открывается в режиме просмотра без контекста пакета, и возврат идёт в поиск, а не в инбокс.

## Просмотр

- [ ] **T-2.9 Рендер кода: подсветка, темы, сворачивание блоков** — 3д · FR-EDITOR-11, FR-EDITOR-12
  - Зависит: T-2.5
  - Готово когда: подсветка синтаксиса корректна для языков фикстуры и приоритетных языков из T-2.29, а для нераспознанного языка файл показывается как обычный текст без пустого экрана; тёмная и светлая темы следуют системной, при смене системной темы открытый файл перекрашивается без переоткрытия и без сброса позиции; функции, классы и блоки условий сворачиваются, в свёрнутом виде видно число скрытых строк; состояние сворачивания сохраняется при переходе между файлами пакета и сбрасывается при открытии файла заново; файл 5000 строк открывается за < 500 мс и скроллится с 60 FPS (NFR-3, профайлер кадров).

- [ ] **T-2.10 Масштаб шрифта жестом «щипок»** — 1д · FR-EDITOR-15
  - Зависит: T-2.9
  - Готово когда: щипок двумя пальцами меняет размер шрифта кода в диапазоне 8–32 pt, не меняя размер шапки и панели кнопок; значение сохраняется между сессиями и между перезапусками приложения и не сбрасывается при открытии другого файла; на десктопе масштаб меняется прокруткой с зажатым Ctrl; при системном шрифте 200 % и максимальном масштабе длинные строки переносятся, горизонтальный скролл не появляется (NFR-11).

- [ ] **T-2.11 Переход к определению и поиск использований** — 3д · FR-EDITOR-13
  - Зависит: T-2.2, T-2.9

- [ ] **T-2.12 Outline файла в bottom sheet** — 2д · FR-EDITOR-14
  - Зависит: T-2.2, T-2.9
  - Готово когда: bottom sheet показывает структуру файла — классы, функции, поля — с уровнями вложенности и номерами строк; тап по элементу прокручивает редактор к его строке и подсвечивает её; при прокрутке кода текущий видимый элемент подсвечен в outline; файл с 200 элементами раскрывается и сворачивается узлов без задержки > 100 мс; для файла без символов или без поддерживаемого языка лист показывает «структура недоступна», а не пустой список.

- [ ] **T-2.13 Long press меню в просмотре** — 2д · FR-EDITOR-16
  - Зависит: T-2.9, T-2.11, T-2.12
  - Готово когда: long press по фрагменту кода открывает меню «Объяснить», «Найти ссылки», «Скопировать», «Править»; выделенный фрагмент подсвечен и передаётся в действие целиком — проверяется копированием трёх строк и вставкой в приложение вне AI Studio; «Объяснить» отправляет фрагмент агенту и показывает ответ, не покидая экран и не теряя позицию; «Найти ссылки» открывает список использований по T-2.11; в режиме управления «Кнопки» (§ 5.5.1) те же четыре действия доступны кнопкой, а long press не открывает меню (FR-A11Y-2); меню из пяти пунктов помещается на экране шириной 360 dp без горизонтального скролла.

- [ ] **T-2.14 Переход между файлами текущего пакета** — 2д · FR-EDITOR-17
  - Зависит: T-2.5, T-2.6, T-2.21 (вне очереди: автосейв при переходе между файлами), T-1.34
  - Готово когда: из просмотра открытого файла пакета можно перейти к следующему и предыдущему файлу пакета, не возвращаясь в инбокс; порядок файлов совпадает с порядком на карточке пакета; на границе списка переход помечается недоступным и не перескакивает в другой пакет; переход сохраняет несохранённые правки через автосейв (T-2.21) и восстанавливает позицию просмотра предыдущего файла при возврате к нему; в пакете из 30 файлов переход между соседними файлами занимает не дольше 300 мс.

## Режим чтения и включение правки

- [ ] **T-2.15 Read-only по умолчанию** — 2д · FR-EDITOR-1, FR-EDITOR-2
  - Зависит: T-2.9
  - Готово когда: файл, открытый из любой из четырёх точек входа, доступен только для чтения — тап по коду не поднимает клавиатуру, курсор не появляется, поле ввода отсутствует; после 20 случайных тапов и нажатий клавиш содержимое файла на хосте не изменилось (хеш файла до и после совпадает — проверено на Android и на десктопе); доступны чтение, копирование, навигация и жесты просмотра; в шапке видно, что открыт режим просмотра, а не правки; приглашение к правке через ИИ доступно в один тап.

- [ ] **T-2.16 Включение правки и снапшот перед первой ручной правкой** — 3д · FR-EDITOR-3, NFR-SAFE-2
  - Зависит: T-2.13, T-2.15, T-1.19
  - Готово когда: правка включается кнопкой «Править» и пунктом «Править» в long press меню; после включения появляется явная индикация режима, а содержимое файла не меняется ни на символ; перед каждой ручной правкой, изменяющей файл, создаётся снапшот `refs/ai/snap/<timestamp>-manual`, повторный вход в правку без изменений и повторное сохранение без изменений второй снапшот не создаёт (NFR-SAFE-2 в объёме T-1.19 не переопределяется); в режиме «Кнопки» правка включается только кнопкой (FR-A11Y-2); если снапшот создать нельзя (хост недоступен), правка не включается и пользователь видит причину с кнопкой повтора; выключение правки возвращает read-only без потери содержимого.

## Точечное редактирование

- [ ] **T-2.17 Правка через ИИ: выделить фрагмент → принять или отклонить diff** — 3д · FR-EDITOR-18
  - Зависит: T-2.16, T-1.1
  - Готово когда: выделение фрагмента и формулировка «что изменить» отправляют запрос агенту в контексте файла и выделения; предложение приходит как diff внутри редактора и показывается подсветкой изменённых строк, сырой unified diff не отображается (FR-DIFF-5); «Принять» применяет ровно предложенный диапазон, «Отклонить» возвращает исходный текст побайтово (хеш совпадает); при ошибке агента или таймауте 60 с исходный текст остаётся нетронутым, пользователь видит причину и кнопку повтора; выделение 500 строк отклоняется с сообщением о лимите, а не подвешивает редактор; принятая правка помечается источником «агент», а не «вы».

- [ ] **T-2.18 Ручной ввод: панель символов, автоотступы, snippets** — 3д · FR-EDITOR-19
  - Зависит: T-2.16
  - Готово когда: панель символов над клавиатурой даёт символы, которых нет на системной клавиатуре (`{}`, `[]`, `<>`, `->`, `_`, `$`, `\`, `|`, `#`, `` ` ``), вставка не сбивает позицию курсора; Enter сохраняет текущий отступ, вставка закрывающей скобки при уже открытой не дублирует её, вставка кавычки внутри строки не создаёт вторую пару; доступны snippets языка минимум для объявления функции и `try/catch`, с переходами по позициям после вставки; ввод 200 символов подряд не теряет ни одного нажатия — проверено на Android-устройстве с автозаменой включённой и выключенной.

- [ ] **T-2.19 Автодополнение через LSP хоста** — 3д · FR-EDITOR-19, § 8.2
  - Зависит: T-2.2, T-2.18
  - Готово когда: после ввода двух символов имени запрос уходит в LSP хоста и список дополнений с типами и краткими описаниями появляется за < 400 мс для файла до 1000 строк; список показывается в компактном листе над клавиатурой и не перекрывает строку ввода; выбор варианта вставляет текст с учётом текущего отступа и позиции курсора, а не в конец строки; при сужении ввода список фильтруется без повторных походов на хост чаще одного раза на 100 мс; для языка без LSP автодополнение отключается, ручной ввод продолжает работать; закрытие списка свайпом вниз не вставляет случайный вариант.

- [ ] **T-2.20 Быстрые действия над кодом** — 3д · FR-EDITOR-20
  - Зависит: T-2.17, T-2.18
  - Готово когда: над выделенным фрагментом доступны «Переименовать переменную», «Изменить значение», «Добавить параметр», «Обернуть в try/catch»; перед применением быстрого действия ставится снапшот `refs/ai/snap/<timestamp>-manual`, после применения — снапшот с суффиксом `-after`; переименование до применения показывает «будет изменено N файлов, M мест» и предпросмотр diff, применение затрагивает все использования символа; «Добавить параметр» предлагает значение по умолчанию и обновляет существующие вызовы; если действие затрагивает публичный API или больше 50 мест, требуется явное подтверждение с описанием последствий и способа отката (§ 6.3); отказ от применения возвращает исходные файлы побайтово (хеш совпадает).

- [ ] **T-2.21 Автосейв, пометка «сделано вами» и выход из редактора** — 3д · FR-EDITOR-4, FR-EDITOR-21, FR-EDITOR-22
  - Зависит: T-2.16, T-2.18
  - Готово когда: правка сохраняется на хосте при уходе с экрана, при сворачивании приложения и через 3 с после прекращения ввода; ручная правка помечена как «сделано вами» и визуально отличается от правок агента в файле и в общем diff пакета, а в git-истории у неё автор-человек (§ 8.3); правка человека, попавшая в общий diff пакета, оформляется новой ревизией пакета (инвариант 2), прежняя ревизия остаётся в истории; убийство процесса клиента сразу после ввода (до 3 с) не теряет набранное — черновик восстанавливается при следующем открытии файла с выбором «применить» или «отбросить»; выход выполняется свайпом назад или кнопкой «К review» без подтверждения, если несохранённых правок нет, и с подтверждением, если автосейв не прошёл; после выхода пользователь попадает в исходный hunk.

- [ ] **T-2.22 Конфликт ручной правки с правкой агента** — 3д · FR-EDITOR-23, § 8.3
  - Зависит: T-2.21, T-1.8
  - Готово когда: если файл, открытый в режиме правки, изменён агентом (ветка `ai/<task-id>`) или другим устройством, сохранение не перезаписывает файл молча, а показывает конфликт: версии агента и пользователя и варианты «Оставить моё», «Принять агентское», «Объединить вручную» (тот же набор, что в T-7.13); выбранный вариант применяется только после снапшота; после разрешения конфликта повторное сохранение проходит без ошибки; ложных конфликтов нет — при одновременной правке разных участков файла 500 строк агентом и человеком сохранение проходит без диалога.

## Состояния и отказы

- [ ] **T-2.25 Состояния экрана редактора** — 2д · § 6.1, NFR-7
  - Зависит: T-2.4, T-2.23
  - Готово когда: реализованы и проверены пять состояний: «пусто» — файл без символов или воркспейс без файлов объясняют, что делать; «загрузка» — скелетон строк, а не пустой экран и не бесконечный спиннер; «ошибка» — что случилось, кнопка повтора, техническая деталь по запросу; «нет связи» — кэшированное содержимое с явной пометкой, ввод и сохранение недоступны с пояснением (§ 3.5), позиция просмотра сохраняется; «нет прав» — указано, какое разрешение нужно (запись в воркспейс) и как его выдать (§ 10.1); пять состояний покрыты не только экраном редактора, но и листами outline (T-2.12), деревом файлов (T-2.24) и вкладкой результатов поиска (T-2.8); отдельно обработан «файл удалён агентом» — предложен diff удаления или возврат в review; отключение сети на 30 с на открытом файле не закрывает редактор и не теряет позицию; переход между состояниями не показывает «белый экран» дольше 300 мс (§ 6.4).

- [ ] **T-2.28 Сквозная проверка этапа: чтение и точечная правка из review-цикла** — 2д · G1, NG3, FR-EDITOR-1..28, FR-CTRL-15, FR-A11Y-4..5
